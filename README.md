# Treevolution website

Clean repository baseline for the Treevolution test website and protected Website Manager.

## Structure

- `.github/workflows/deploy.yml` — validates and deploys **only** to the configured `/test` directory.
- `assets/` — current branding, CSS, JavaScript, icons and curated website photography only.
- `client/` — one protected Website Manager: login, dashboard, add/manage project updates and performance view.
- `content/` — client-created project data and uploaded WebP images.
- `our-work/projects/` — SEO project pages generated by the Website Manager.
- `tools/audit_site.py` — deployment gate for links, staging noindex, media integrity, duplicates and repository cleanliness.
- Public page folders (`about/`, `services/`, `our-work/`, etc.) — current website only.

## Repository rule

Do not add versioned runtime files/folders (for example `v6`, `v7`, `client-update`) or duplicate/unused media. Replace current files in place. Historical notes belong in Git history, not in the working tree.

## Private configuration

`client/.treevolution-config.php` is generated during deployment from GitHub secrets. It must never be committed. The root `.htaccess` also denies direct HTTP access to that file.

## Staging

This branch is intentionally configured for the Treevolution `/test` site: `robots.txt`, page meta tags and HTTP headers prevent indexing. Do not switch the deployment path or indexing controls until the client approves the live launch.
